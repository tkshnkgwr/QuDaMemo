## 1. 開発原則と基本ルール

QuDaMemo プロジェクトへの参加および修正にあたっては、以下のルールを遵守してください。AI エージェントを含むすべての開発者は [RULES.md](../../RULES.md) を最優先で遵守します。

1. **破壊的変更の禁止**: 明示的に指示された箇所以外のスタイル・挙動・コンポーネント構造を変更しないこと。
2. **Markdown テーブルの垂直整列**: ドキュメント内の表組みは、生テキスト（gVim 等）で閲覧した際にも一目で構造がわかるよう、パイプ `|` とハイフン `-` を垂直整列（文字幅考慮パディング）させること（[markdown-table スキル](file:///.agents/skills/markdown-table/SKILL.md) 準拠）。
3. **パス表記の環境変数化原則**: ソースコード、設定、ドキュメントにローカル絶対パスを記述する際は、ユーザー名をハードコードせず、必ず `%USERPROFILE%` 等の環境変数またはリポジトリ内相対パスを使用すること。
4. **迅速なドキュメント修正**: 修正対象が Markdown（`*.md` のみ）の場合は、事前検証コマンドを省略して迅速に対応すること。
5. **多言語ドキュメントの同期**: 仕様や機能に変更があった場合は、日本語（`docs/ja/`）と英語（`docs/en/`）の両方を同期更新すること。

## 2. コミット規約

コミットメッセージは、以下のプレフィックスを用いた明確な規約に従います（詳細は [git-commit スキル](file:///.agents/skills/git-commit/SKILL.md) 参照）：

| プレフィックス | 用途・対象                                                     |
| :------------- | :------------------------------------------------------------- |
| `feat:`        | 新機能の追加                                                   |
| `fix:`         | バグ修正                                                       |
| `docs:`        | ドキュメント・仕様書の追加・修正                               |
| `refactor:`    | 振る舞いを変更しないコードの改善・モジュール分割               |
| `perf:`        | パフォーマンス向上・低リソース最適化                           |
| `test:`        | テストコードの追加・更新                                       |
| `release:`     | バージョンバンプおよび公式リリース準備                         |

> [!CAUTION]
> Git への追加・コミット・Push を AI が自律判断で自動実行することは **一切禁止** されています。必ずボス（ユーザー）からの明示的な指示があった場合のみ実行してください。
